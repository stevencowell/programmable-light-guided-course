Exclude all Stage 5 PICAXE material. Do not display a task number, weighting, marks, issue date, due date or formal assessed-outcome claim. None is supplied by the authorised source.

Use **TASK 10 Programmable Light** as the site/project label. Preserve **Programmable Lamp** when naming or quoting the supplied drawing and worksheets. This project label is not formal assessment metadata.

## Folio-card records - exactly 12

### Folio card 01 - Project purpose and success criteria

- **Record ID:** `folio-card-01`
- **Intended module link(s):** `modules/01-start-safely.html#folio-card-01`
- **Student action:** Define what a successful programmable light should achieve.
- **Required evidence:** a short project explanation; class-agreed criteria under design, function, construction/build quality, electronics and programming, and aesthetics; one personal goal.
- **Response prompt:** What will make your programmable light successful, and what will you personally try to do well?
- **Sentence starters:** `A successful programmable light should...` / `My personal goal is... because...`
- **Photo field:** optional example or inspiration image field; photo requirement **Teacher to confirm**.
- **Caption field:** `This image is useful because it shows...`
- **Source field:** title/URL/creator field; prefill the authorised Unit Introduction worksheet when used.
- **Outcome alignment:** TE4-PPM-01, TE4-DES-01.

## Autosave, backup and Print / Save PDF contract

Apply this behaviour to all 12 card records:

- Create an opaque local record ID so multiple records do not overwrite one another on a shared browser profile.
- Store text, selections, tables, checklist state, captions, source fields and card-completion state under a versioned key such as `task10-programmable-light:<local-record-id>:folio-card-XX:v1`.
- Autosave on meaningful input/change and show `Saved on this device` with the latest local timestamp.
- Restore the same local record after reload. Provide record switching only if the implementation can do so without exposing another student's work.
- Provide `Download folio backup` as JSON containing all 12 text/state records, schema version, local record ID and saved timestamp. Provide `Restore folio backup` with validation and a replace/keep-both choice.
- Do not put large photo binaries in `localStorage`. If tested IndexedDB photo persistence is implemented, label it device-local. Otherwise state visibly that photo files are not included in autosave or JSON backup and must be kept separately/reselected before printing.
- Provide a confirmed reset action. Reset must identify the exact local record and must not silently clear another record.
- State on every module: browser storage is specific to this browser/profile/device and is not cloud submission.
- `Print / Save PDF` must output exactly 12 folio pages, one card per page, in card order. Expand text areas and tables, show selected images available in the session, print captions and source URLs, repeat student/local-record identification, and hide navigation, save/reset controls and incomplete-state prompts.
- Before printing, show a completion summary of complete, started and blank cards. This is workflow information, not a mark.
- The only source-confirmed submission action is the Week 03 exported practice design to Google Classroom; the actual Classroom destination and every other submission value are **Teacher to confirm**.
